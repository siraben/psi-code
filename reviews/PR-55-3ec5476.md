## Project intent

The PR adds MCP (Model Context Protocol) stdio-server support so psi can advertise tools dispatched to external processes. It introduces a new bidirectional C process primitive (`psi_process_begin_stdio_argv` + write/close_stdin/terminate, plus SIGPIPE save/restore and abort-aware SIGKILL escalation), an FFI surface in `src/lua/vm.c`, a Lua-owned MCP client at `lua/psi/mcp.lua` (initialize/tools/list/tools/call), `/mcp` and `/status` slash commands, auto-registration of Forgejo and Linear MCP servers from env vars, and Nix wrappers that put `forgejo-mcp` and `linear-mcp` on `PATH` for the default package. The architectural shape — narrow C primitive, Lua-owned protocol — fits the "host stays small, policy in Lua" rule documented in `docs/architecture.md`.

## Blocking findings

### 1. Boot-time MCP startup blocks every CLI invocation up to N×10s

**path:** `lua/psi/tools.lua:23-28`

**Observable:** `lua/psi/tools.lua:25` calls `mcp.register_configured_servers(registry, records)` at module load. `lua/boot.lua:44` does `psi.tools = require("psi.tools")` unconditionally during VM init. `register_configured_servers` (mcp.lua:448) iterates servers serially; each `Client:start()` fork+execs the MCP child then synchronously calls `Client:request("initialize", …, self.timeout_ms)` (mcp.lua:344) followed by paginated `Client:list_tools()` (mcp.lua:358-374). Default `self.timeout_ms` is `DEFAULT_TIMEOUT_MS = 5000` (mcp.lua:12).

Forgejo + Linear auto-register from env vars alone (mcp.lua:418-443), so users who set `FORGEJO_ACCESS_TOKEN` in their shell will pay this cost on every psi process — including `--eval`, `--print`, `--system-prompt`, `--compact`, `--agent`, REPL, and TUI.

**Consequence:** with N configured servers (auto + user), worst-case startup blocks `N × (5s init + 5s × pages)` before the first byte of output, on every CLI invocation. The smoke-test `tool/mcp_timeout_does_not_hang` (tests/smoke.py:643) demonstrates this exact path with a 100ms override; the default is 50× larger.

**Fix direction:** defer MCP registration until the first agent turn (lazy init in `agent_session`/`provider_loop`), or skip it in non-agent modes (`run_eval`/`run_print`/`run_system_prompt`); alternatively, parallelise via `sched.run_all` so initialization is bounded by the slowest server, not the sum.

## Should-fix findings

### 2. session-shutdown never fires in `--print`/`--eval`/`--agent`/`--compact`; MCP children leak

**path:** `lua/boot.lua:46`

**Observable:** `lua/boot.lua:46` wires `psi.events.on("session-shutdown", psi.mcp.shutdown_all)`. `psi.events.emit("session-shutdown", …)` is invoked exactly once, from `session.announce_shutdown` (`session_manager.lua:917-926`). Greppage shows `announce_shutdown` callers are only `modes.lua:331,337` (REPL) and `tui_runtime.lua:2700` (TUI). `M.run_print`, `M.run_eval`, `M.run_system_prompt`, `M.run_agent`, and `M.run_compact` (`modes.lua:91-174`) all return without calling it.

**Consequence:** in `--agent` and `--print`, after the agent turn finishes, `Client:shutdown` is never called, so MCP child processes (`forgejo-mcp`, `linear-mcp`) keep running until the parent exits and the OS reaps them via the userdata `__gc` (`vm.c:1467-1478`). For the bundled remote-network children that's a token-bearing process outliving its purpose.

**Fix direction:** call `announce_shutdown` (or directly `psi.mcp.shutdown_all`) at the end of every mode handler in `lua/psi/modes.lua`, or register `psi.mcp.shutdown_all` with an `atexit`-style C hook that does not depend on the session-shutdown event.

> Quoted rule (`docs/architecture.md`, "Sessions and lifecycle events"): "a shutting-down frontend emits one `session-shutdown`; every frontend should use the same lifecycle semantics."

### 3. Forgejo auto-config silently defaults to codeberg.org when only the token is set

**path:** `lua/psi/mcp.lua:418-435`

**Observable:** the auto-Forgejo branch (mcp.lua:419-422) fires when **either** `FORGEJO_ACCESS_TOKEN`/`GITEA_ACCESS_TOKEN` **or** `FORGEJO_URL`/`GITEA_HOST` is set. Then `args = { …, "--url", url or "https://codeberg.org" }` defaults the URL.

**Consequence:** a user whose `FORGEJO_ACCESS_TOKEN` is for a private/self-hosted Forgejo (the typical case) but who has not exported `FORGEJO_URL`, will on first boot hand that token to `forgejo-mcp` pointed at `codeberg.org`. The token is then transmitted to a third party they did not intend to talk to. Codeberg will reject it, but the secret has been disclosed off-host.

**Fix direction:** require **both** a URL **and** a token before auto-registering; if only a token is set, log a stderr hint ("Forgejo auto-MCP skipped: set FORGEJO_URL").

### 4. `psi_process_write` blocks the TUI scheduler

**path:** `src/core/process.c:267-318`

**Observable:** `psi_process_write` loops until the entire request is written, sleeping `nanosleep(20ms)` on `EAGAIN`. It checks `abort_signal` at the top of each loop, but never invokes `psi.host_tick()` and never yields to `psi.sched`. `lua/psi/mcp.lua:203` calls `psi.process_write` directly (no scheduler wrapper exists). Default Linux pipe buffer is 64 KiB, so this normally never matters, but a slow / paused MCP child will fill the pipe and stall the writer.

**Consequence:** while a stuck write is in progress, the TUI cannot redraw, cannot pump input, and Ctrl-G is observed only on the next 20 ms abort poll. The architecture rule "`psi.host_tick()` lets the UI keep pumping input and redraw while a provider stream or shell process is in flight" (`docs/architecture.md` §"Cooperative scheduler") is violated for the new write path. Writes are small in well-behaved scenarios but the invariant is now conditional on server liveness.

**Fix direction:** make stdio writes scheduler-aware — yield through `psi.sched` between non-blocking write attempts (mirroring `proc_poll` for reads), or expose a non-blocking `psi.process_try_write` that returns short-write counts and let `mcp.lua` drive the loop from a coroutine.

### 5. `command_label` only redacts `--token`; other secret-bearing flags leak into `/mcp` and `/status`

**path:** `lua/psi/mcp.lua:103-142`

**Observable:** the redactor at mcp.lua:116-124 recognises only `--token`, `-token`, and `--token=…`/`-token=…`. A configured server such as `{ command = "foo-mcp", args = {"--api-key", "sk-...", "--bearer", "tok"} }` has its args appended verbatim to `parts`. `status_text` then prints `status.command` (mcp.lua:593-594) when the user runs `/mcp` or `/status` (slash_commands.lua:739-743).

**Consequence:** secrets passed via `--api-key`, `--password`, `--auth`, `--header "Authorization: Bearer …"`, `--secret`, `--access-token`, etc. are exposed in interactive output and may end up in `/copy` / `/export` transcripts. (Env-derived secrets like `FORGEJO_ACCESS_TOKEN` are safe **by accident** — they live in `cfg.env`, which `command_label` does not inspect; the smoke check at `tests/smoke.py:775` validates this incidentally.)

**Fix direction:** maintain a stem denylist (`token`, `key`, `api-key`, `apikey`, `password`, `pass`, `secret`, `auth`, `bearer`, `authorization`, `header`) and redact `--<stem>` followed by a value or `--<stem>=…`; consider entropy-based redaction of any value that looks bearer-token-shaped.

### 6. Re-registration leaves stale tools bound to dead `Client` upvalues

**path:** `lua/psi/mcp.lua:448-456`, `lua/psi/tool_registry.lua` (no unregister API)

**Observable:** `register_configured_servers` resets module-local state (`clients`, `registered`, `statuses` at mcp.lua:451-456), but the `Tool` records added via `registry.register(records.new_tool(local_name, …, function(input) ... client:call_tool(...) ... end, ...))` (mcp.lua:508-526) survive in the global tool registry. `tool_registry.register` only replaces by exact name match (`tool_registry.lua:27-35`); there is **no `unregister`**. Any second invocation (e.g. after `/reload` or a future explicit MCP reset) that drops a server or renames a tool leaves orphaned `mcp_*` entries whose closure captures the now-shut-down `client` (its `handle` was nil'd at mcp.lua:451-453).

**Consequence:** model calls the leftover tool → `Client:call_tool` → `Client:send` → `"MCP server is not running"` → returned as an error tool result. The provider keeps offering a tool that can never succeed, with no operator-visible reset path. Note: `cmd_reload` in `slash_commands.lua` reloads settings but never re-runs `register_configured_servers`, so the symptom is currently dormant — but the contract is broken and the next reload-related change will surface it.

**Fix direction:** add `tool_registry.unregister(name)`; track previously-registered names in a module-level set in `mcp.lua` and unregister them before re-registering; have `cmd_reload` call `psi.mcp.register_configured_servers` after `psi.settings.reload()`.

### 7. `Client:next_line` buffer is unbounded — DoS by a misbehaving MCP server

**path:** `lua/psi/mcp.lua:227-259` (esp. line 252)

**Observable:** `Client:next_line` does `self.buffer = self.buffer .. chunk` until a newline appears. The C-side 256 KiB cap (`PSI_PROCESS_OUTPUT_MAX_BYTES`, process.c:17) only limits the handle's *internal* finish buffer; `psi_process_poll` still returns each fresh 4 KiB read to the caller (process.c:381-410). A misbehaving local server, or — more importantly — a hostile remote MCP service reachable through the bundled `mcp-remote` bridge, can stream newline-free bytes forever.

**Consequence:** psi grows the per-client `self.buffer` without bound, plus pays an O(n) Lua string concat per 4 KiB chunk (quadratic total work). 10 MB of newline-free input is ~50 GB of copies before OOM, with no operator signal beyond eventual death.

**Fix direction:** enforce a per-line maximum (e.g. 4 MiB), abort the client with a protocol error on overflow, and surface a clear stderr line. Bonus: switch to a rope/table-of-chunks accumulator to make the concat cost linear.

## Nits

### 8. `read_message` swallows non-table JSON lines silently

**path:** `lua/psi/mcp.lua:288-298`

`safe_json_decode` returns the fallback `nil` on parse error (`prelude.lua:187-196`). `read_message` returns `nil` (no error) for any non-table value. `Client:request` (mcp.lua:300-327) sees `msg=nil, read_err=nil` and just spins until deadline, producing only `"timeout waiting for MCP <method>"`. Operators debugging a misbehaving server (e.g. one that emits a startup banner before JSON) get no hint that bytes were received and discarded. Surface a one-line stderr like `psi: MCP <name>: invalid line dropped (<truncated>)`.

### 9. `tools/list` pagination has no cycle detection

**path:** `lua/psi/mcp.lua:358-375`

The cursor loop terminates only on `nextCursor == nil or ""`. A buggy server echoing the request cursor back would loop indefinitely (no per-iteration timeout fires; only the inner `request` does). Track the previous cursor and break with a logged warning when it does not change; cap total pages at, say, 256.

## Architecture observations

- The shape of the integration matches the documented "host stays small, policy in Lua" rule: only a minimal write/poll/close surface is added in C, with all framing, JSON-RPC, name mapping, and dispatch in `lua/psi/mcp.lua`. This is the right factoring.
- Codex's suggestion to gate `psi.process_begin_stdio_argv` through `psi.runtime_info()` is a desirable future improvement but not currently load-bearing — `mcp.lua:330` already degrades cleanly when the function is missing, and on Windows the C stub returns ERROR which surfaces as a per-server start error. Treat as a follow-up alongside other capability gates rather than a PR blocker.
- The new `psi.process_*` surface is now part of the documented public Lua API (extensions.md). Any extension can spawn arbitrary processes with arbitrary env. This is not a meaningful new privilege over `psi.process_run`, but it does broaden the target surface; future hardening (e.g. an extension permission gate) should consider it.

## Follow-ups

- Add `tool_registry.unregister(name)` — needed for #6 and likely useful for any future dynamic-tool source (skills, runtime extensions).
- Consider a generic `psi.atexit(fn)` host-level hook for cleanup that must run even in `--print`/`--eval` paths (covers #2 and any future external resource).
- Document MCP boot-time cost in README (and the `mcp.timeout_ms` knob) so operators understand the latency they're paying. Also document that env-bearing args are not redacted in `/mcp` until #5 lands.

## Limitations

- No build was run as part of this review (cross-validators reported `cc` not on `PATH` in the codex sandbox; the local Claude reviewers used file inspection only). The PR's CI run on Forgejo was not consulted.
- The Windows MCP path was inspected for stub completeness only; a full Windows port is out of scope per `docs/port-status.md`.
- Live MCP behaviour against actual `forgejo-mcp` / `linear-mcp` was not exercised; smoke tests cover the protocol shape with a Python mock.
- `mcp-remote` (the Node.js bridge to remote MCP services) was not source-reviewed; only its surface as called from `flake.nix` was considered.
