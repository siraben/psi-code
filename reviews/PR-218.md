## Author intent

> - stop promoting terminals shorter than 12 rows to a synthetic 12-row inline frame
- size the prompt viewport like pi-mono: `max(5, floor(terminalRows * 0.3))`
- cap that target to physically available rows in frame mode while allowing chat mode to scroll its five-row minimum naturally
- crop unavoidable tiny-frame chrome around the actual editor cursor marker, keeping emitted height and hardware

## Codex track (discovery)

```
PARITY_VERDICT: PARTIAL — pi computes the editor cap from the physical terminal height as `max(5, floor(rows * 0.3))` and scrolls the visible slice around the cursor (`packages/tui/src/components/editor.ts:499-519`). pi’s renderer likewise reads physical terminal rows directly (`packages/tui/src/tui-main-screen.ts:180-205`); psi matches when its inline frame equals the terminal height, but derives the cap from the synthetic inline-frame height when `PSI_TUI_INLINE_MAX_ROWS` is smaller.
FINDINGS:
- title: Prompt cap uses inline frame height instead of terminal rows
  path: lua/psi/tui_runtime.lua line: 506-511
  severity: should_fix
  category: bug
  reason_flagged: The new 30% calculation receives `state.height`, which may already be reduced by `PSI_TUI_INLINE_MAX_ROWS`, rather than the retained physical `state.terminal_height`.
  body: On a 100-row terminal with a 20-row inline frame, the default target becomes 6 rows even though pi's target is 30 and the frame-mode physical cap permits 14 -> multiline input scrolls eight rows earlier than necessary -> calculate the default from `state.terminal_height` and apply the frame-space cap separately using `state.height`.
- title: Prompt row API documentation no longer matches chat mode
  path: docs/extensions.md line: 352
  severity: nit
  category: api_boundary
  reason_flagged: The documented guarantee that the final prompt limit is always clamped to terminal height became false when chat mode stopped applying that clamp.
  body: `input_max_rows` now deliberately permits chat's five-row minimum on a four-row terminal, while the public extension documentation still promises an unconditional physical-height clamp -> extension authors receive an incorrect contract -> document the frame-mode clamp and chat-mode natural-scrolling exception.
PI_GAPS:
- With `PSI_TUI_INLINE_MAX_ROWS` below the physical terminal height, psi bases the 30% target on the reduced frame, whereas pi always bases it on `this.tui.terminal.rows` (`packages/tui/src/components/editor.ts:499-501`).
```
