## Project Intent

PR 55 adds stdio MCP server support: psi can launch configured MCP servers, negotiate tools over JSON-RPC, register discovered tools into the existing Lua tool registry, expose `/mcp` and expanded `/status`, and package auto-configured Forgejo and Linear MCP bridges in the Nix build.

## Blocking Findings

### Blocking stdio writes can wedge the Lua runtime

`src/core/process.c:249`

`psi_process_begin_exec` sets `O_NONBLOCK` only on the child stdout pipe at `src/core/process.c:172`, but stores the child stdin write fd at `src/core/process.c:187` without making it nonblocking. `psi_process_write` then loops synchronously on `write(h->stdin_fd, data + written, len - written)` at `src/core/process.c:249`, and `lua/psi/mcp.lua:298` calls it before the MCP request deadline begins at `lua/psi/mcp.lua:303`.

Consequence: if an MCP child stops reading stdin, or a large `tools/call` payload exceeds the pipe buffer, the single Lua owner thread blocks inside `write()`. MCP `timeout_ms`, TUI host ticks, and abort checks are not observed until the child drains or exits.

Repro run locally:

```sh
env -u FORGEJO_ACCESS_TOKEN -u GITEA_ACCESS_TOKEN -u FORGEJO_URL -u GITEA_HOST \
  -u LINEAR_API_KEY -u LINEAR_MCP_AUTO \
  timeout --kill-after=1s 3s ./build/psi --eval \
  'local h = assert(psi.process_begin_stdio_argv({"python3","-c","import os,time; p=os.getppid();\nwhile os.getppid()==p: time.sleep(0.1)"})); local ok = psi.process_write(h, string.rep("x", 1024 * 1024)); return tostring(ok)'
```

It exited with `status=124`, proving the timeout wrapper had to kill psi.

Fix direction: make stdio stdin writes nonblocking and pollable, then drive partial writes through the scheduler/deadline/cancel path. A smaller mitigation is to enforce a bounded write and return a structured MCP error before blocking, but that still leaves protocol-sized requests fragile.

Relevant psi rule: "Treat cancellation as consistency-sensitive. Aborts should stop future work, persist coherent tool/session state, and allow the next turn to start normally."

## Should Fix Findings

### MCP tool names can exceed Anthropic's 64-character limit

`lua/psi/mcp.lua:42`

`sanitize_name` truncates MCP local tool names to 96 characters, and collision suffixing at `lua/psi/mcp.lua:54` also reserves against a 96-character cap. The Anthropic adapter sends tool names unchanged from `t.name` at `lua/psi/anthropic.lua:77`.

Consequence: a configured MCP server with a long server/tool name can register successfully, but the next Anthropic request can fail before the model responds because Anthropic documents tool names as matching `^[a-zA-Z0-9_-]{1,64}$`. I reproduced a 96-character registered MCP tool name locally.

Fix direction: cap generated local MCP names to 64 characters, reserve room for suffixes, and add a short hash or stable disambiguator so long names remain unique.

Source: Anthropic tool-use docs, "Specifying client tools" (`name` field): https://docs.anthropic.com/en/docs/agents-and-tools/tool-use/implement-tool-use

### MCP shutdown SIGTERMs instead of closing stdin first

`lua/psi/mcp.lua:215`

`lua/boot.lua:45` registers `psi.mcp.shutdown_all` on `session-shutdown`, and `session.announce_shutdown` emits that event at `lua/psi/session.lua:910`. `Client:shutdown()` then calls `psi.process_terminate(self.handle)` whenever that primitive exists, so the `process_close_stdin` branch at `lua/psi/mcp.lua:217` is dead in normal builds.

Consequence: normal psi shutdown sends SIGTERM instead of first signaling EOF on stdin and giving MCP servers a chance to flush or clean up. This violates the stdio MCP lifecycle expectation and can lose server cleanup behavior.

Fix direction: close stdin first, poll/wait briefly for normal exit, call `process_finish`, and only terminate after a shutdown timeout. Add a smoke server that records whether it saw EOF versus SIGTERM.

Source: MCP lifecycle spec, stdio shutdown: https://modelcontextprotocol.io/specification/draft/basic/lifecycle

### Non-numeric MCP timeout settings crash bootstrap

`lua/psi/mcp.lua:303`

`configured_servers()` returns `cfg.timeout_ms or DEFAULT_TIMEOUT_MS` at `lua/psi/mcp.lua:437` with no numeric validation. `Client.new` stores that value at `lua/psi/mcp.lua:191`, and `Client:request` does `psi.time_ms() + (timeout_ms or self.timeout_ms)` at `lua/psi/mcp.lua:303`.

Consequence: a malformed project or global settings file such as `"timeout_ms": "bad"` aborts Lua bootstrap while loading `psi.tools`, so psi does not start and the MCP server is not merely marked unhealthy.

Repro run locally:

```text
failed to load Lua bootstrap: .../lua/boot.lua
[string "psi.mcp"]:303: attempt to add a 'number' with a 'string'
status=1
```

Fix direction: coerce with `tonumber`, clamp to a sane range, and default invalid values. If a per-server timeout is invalid, report that server in MCP status instead of throwing during registry bootstrap.

### Forgejo auto test does not assert URL/transport wiring

`tests/smoke.py:609`

The Forgejo auto-registration smoke test sets `FORGEJO_URL` at `tests/smoke.py:639`, and production code builds `--transport stdio --url <url>` at `lua/psi/mcp.lua:416`, but the mock server only asserts `--token` at `tests/smoke.py:609`.

Consequence: a regression that drops the custom URL or transport flag would still pass while breaking self-hosted Forgejo auto-registration.

Fix direction: have the mock validate `--transport stdio` and `--url https://forgejo.example.invalid`; add a URL-only case if auto-registration should work without a token.

## Architecture Observations

The main design direction is good: MCP protocol handling, JSON-RPC, tool naming, and tool registration are Lua-owned, while C only exposes a bidirectional process primitive. The biggest architectural gap is that stdin writes are not yet part of the same pollable/cooperative process model as stdout reads.
